# 收支分类与数据结构设计（v8，公开版）

- 状态：已在 expensify 上线（v0.4.1）：类别、收入、回款、账本、支付方式、信用卡费用与免除；租金只记在出租账本
- 货币：新币 S$。历史数据由旧 app 人民币记录按固定汇率换算后导入（B-03）
- 公开版（2026-10-09，B-30）：去掉了历史金额、税费和医疗明细、成员和房产 tag 的取值、与家庭相关的商家名称，以及历史数据核对和清理（原第 2b、2c 节和 2026-10-04 的决策记录）。完整的 v8 和历史数据保存在私有存档仓库 `huiminlatsg/dragon-turtle-ledger`，只在历史导入时使用

---

## 1. 设计原则

1. **类别只表示用途。** 商家、付款渠道、为谁花的钱都不进类别名，改用独立字段（商家、支付卡、成员、房产）。
2. **两层结构：大类 → 类别**，支出和收入对称。
3. **每个大类有「性质」标记**，报表默认只看生活消费和真实收入。
   - 支出性质：**生活消费** / **财务支出** / **过手款**
     - 生活消费、财务支出：都是真实流出，计入支出报表、现金流和预算
     - 过手款（代付款大类）：会有回款，不占支出和预算；只有其中的自付部分计入支出
   - 收入性质：真实收入 / 冲减项
4. **钱会回来的部分用「可回款金额」记录。** 记账时就把一笔支出拆成「自己花的」和「会收回来的」两部分；只有会收回来的部分进入待回款池，报表剔除，信用卡 min-spend 仍按刷卡全额计算。

### 支出类别说明

- **房产税、印花税** 放在住房，算住房成本；不放在税费。
- **税费** 今后主要是所得税和各类费用。**手续费、卡年费、滞纳金利息**都可被「手续费免除」冲减：免除到账后关联到原费用，原费用就不再算支出。
- **信用卡费用**（年费、滞纳金、利息、手续费）刷在卡上、随账单还款，但**永远不计入 min-spend**；之后被免除时，免除金额也不影响 min-spend。
- **税费（历史未拆分）**：旧数据中税费混记，历史数据已拆开，不再有这一类别；它只保留在种子数据里。
- **课外班** 只用一个类别，具体课程用 **商家** 字段区分；报表按商家看每个课外班的月度、年度花费。
- **学费** 独立保留，不是课外班。
- **用车** 是车辆持有和使用成本（车贷、车险、路税、加油、停车过路、保养维修）。**出行** 是按次付费的公共交通和打车。两者分开大类。
- **全额报销的医疗开销**：记账时可回款金额 = 全额，状态 = 已到账，报表不计入生活消费。体检是医疗健康下的新类别。
- **投资买卖是转账，不是支出。** 银行账户 ↔ 投资账户的资金移动记为转账（第 11 节）。银行账户与投资账户之间的资金流动及其对银行余额管理的影响，是以后的阶段（见 RTM 第 12 节）。
- **生日会**：场地、活动、包场费记在 休闲娱乐 / 娱乐活动，商家写场地名，备注写是谁的生日会，成员 tag 选过生日的人。同一场生日会的食物蛋糕记餐饮，回礼和小礼物记 人情往来 / 礼物；订金、尾款分别记两笔，备注写清楚。
- **年票**：休闲娱乐 / 年票（类别已有），商家写景点名，成员 tag 选持票人。年票按付款日一次性记，不按月摊销。
- **手机电话** 如实记录，不做清理。
- **超市** 一个类别，商家另记。
- **网购** 不再是大类；Lazada、Amazon 等按买的东西归类，平台记在商家。
- **代付款** 大类（原「报销代付」）按**场景**归类：出差、替人垫付相关的花销都记在这里，用小类区分是餐费、交通、话费等。日常的餐饮、出行才记到餐饮、出行大类。
- 「代付款」小类专门记纯粹替别人垫的钱，与自己的消费无关。

## 3. 收入结构（4 个大类）

| 大类 | 性质 | 类别 | 说明 |
|---|---|---|---|
| 投资收入 | 真实收入 | 投资收益 · 股息分红 · 利息 | 报表可合并看「投资总回报」 |
| 租金收入 | 真实收入 | 租金 | **只能记在出租账本里**（自动带上房产 tag）；不计入家庭收入，只进该房产的损益 |
| 回款类 | 冲减项 | 报销到账 · 代付款收回 · 退款 · 手续费免除 · 返现 | 必须填收款账户。前四项可关联原支出（见第 6 节）；返现是信用卡 cash rebate，不关联支出 |
| 其他 | 冲减项 | 漏记/差额平账 | 对账兜底，默认不计入真实收入 |

## 3a. 账本

每笔交易属于一个账本。每个家庭默认有一个「日常账本」，记账时不选就记到这里。

| 类型 | 计入家庭总支出 | 用途 |
|---|---|---|
| 日常 | 是 | 日常生活收支 |
| 旅行 | 是 | 每次旅行一个账本，可设起止日期和默认币种（外币） |
| 房产出租 | **否**，单独看损益 | 每套出租房一个账本，记录这套房的全部租金收入和出租开销；账本内交易自动带上该房产 tag |

- 类别所有账本共用，另有账本专属大类（见第 2 节）。
- 报表可只看某个账本、只看日常账本，或合并「计入家庭总支出」的账本。
- 预算可按账本设置（例如一次旅行的总预算）。
- min-spend 统计一张卡在所有账本中的刷卡。

## 6. 报销 / 回款机制

**状态流转**

1. 记支出时填写可回款金额 → 状态 = **待提交**
2. 提交报销（或告知对方还款） → **已提交待到账**，可回款部分进入待回款池
3. 收到回款并关联 → **已到账**，退出待回款池

AA 这类朋友直接还钱、不需要「提交」的，可以记账时直接设为「已提交待到账」。

**待回款池** = 所有状态为「已提交待到账」的支出的**可回款金额**之和，随时可查，相当于应收款。自付部分从一开始就算自己的消费，不进池子，因此池子里不会挂尾款。「待提交」的金额单独显示，提醒还没提交。

**记录回款的两种方式（并存）**

- **勾选关联**：记一条回款类收入，勾选它对应的一笔或多笔支出。勾选的支出自动变为「已到账」并退出池子。一对一时勾一笔即可。
- **按总额冲减**：只记回款金额，不勾具体支出。只有**报销到账**和**代付款收回**会这样直接减少池子总额；之后可以补勾。退款和手续费免除只有关联到原支出时才影响池子。
- 关联到一笔原本没有可回款金额的支出（例如手续费免除对应手续费）时，系统自动把这笔支出的可回款金额设为回款金额（不超过支出金额），并标记为已到账。

**金额不一致**：如果关联支出的可回款金额合计与回款金额不同（例如公司少批、朋友少还），差额显示在这条回款上。少收的部分有两种处理：继续留在池子里等待，或确认收不回来，把该笔支出的可回款金额调低，差额转为自付。

退款、手续费免除、代付款收回使用同一套机制。

## 7. 报表口径

所有支出报表、现金流和预算都以**自付金额**（金额 − 可回款金额）为准。

- **生活消费** = 生活消费大类的自付金额之和
- **财务支出** = 保险理财 + 税费的自付金额之和，在报表中作为支出流水单独展示
- **总支出（计入预算）** = 生活消费 + 财务支出 + 过手款中的自付部分
- **过手款** = 代付款大类。默认可回款金额 = 全额，不占支出和预算；若有收不回的部分（例如出差未全额报销），差额作为自付计入总支出，并在报表中单独列出
- **预算**：可按大类设置，适用于生活消费和财务支出；代付款大类不设预算
- **信用卡 min-spend** = 该卡所有支出的**金额全额**（不扣可回款金额）− 退回这张卡的**退款**。信用卡**返现**不计入 min-spend。卡年费、滞纳金利息、手续费不计入 min-spend，它们的免除也不计入。朋友还钱、报销到账一般进银行或现金账户，不影响信用卡。
- **家庭真实收入** = 投资收入（不含回款类和其他）。**租金不计入家庭收入**，只出现在对应房产的损益里
- **每套房净收益** = 该房产出租账本里的租金收入 − 出租开销（以及其他打了这套房产 tag 的开销）
- **投资总回报** = 投资收益 + 股息分红 + 利息
- **待回款** = 待回款池金额 + 待提交的可回款金额

## 11. 支付方式（v0.4.0）

### 账户类型

| 类型 | 余额含义 | 设置 |
|---|---|---|
| 信用卡 | 负数 = 欠款 | 账单日、还款日（每月固定某天，或账单日后 N 天）、额度、年费月份、充值是否默认计入 min-spend（默认否）、min-spend / bonus cap 规则（按自然月或账单周期） |
| 银行账户 | 账户里的钱 | 期初余额和日期，按银行对账单对账 |
| 借记卡 | —（直接从关联的银行账户扣钱） | 关联银行账户 |
| 储值账户 | 卡里/钱包里的钱 | 期初余额，可用银行转账或信用卡充值 |
| 现金 | 可选 | — |

每个账户只有一种币种，暂不做多币种钱包。暂不设附属卡。PayNow 记在对应的银行账户上。

### 转账（第三种交易类型）

自己账户之间的资金移动记为**转账**：有转出账户和转入账户，没有类别，不算支出也不算收入。

| 场景 | 转出 → 转入 |
|---|---|
| 还信用卡账单 | 银行 → 信用卡（现阶段手动记录） |
| 储值卡充值 | 银行或信用卡 → 储值账户 |
| 取现金 | 银行 → 现金 |

储值账户的消费在**使用时**记支出（例如用 GrabPay 付打车），充值只是转账，所以不会重复计算。

**信用卡充值储值卡**：每笔充值都有「是否计入这张卡的 min-spend」选项，默认值取自这张卡的设置（默认否），记账时可以改。

### 余额与对账

- **余额** = 期初余额 + 期初日期之后的所有收支和转账。借记卡的消费计入它关联的银行账户。
- **对账单**（银行和信用卡通用）：录入账单期间、期初和期末余额（信用卡另有还款日，没填时按卡的设置自动算）。账单明细逐行对应到已记录的交易。
- **对账检查**：显示未匹配的账单行（多半是漏记）、未匹配的交易（多半是金额、日期或账户记错），以及明细合计是否等于期末减期初。
- **全部对上才能标记为已对账**；已对账账单里的交易会被锁定，修改前要先把账单改回未对账。
- **信用卡账单状态**：应还金额；从账单日到下一期账单日之间的还款（转入这张卡的转账），以及还款日前已还的部分；状态为已还清 / 逾期后还清 / 部分已还 / 未还 / 已逾期。
- 自动读取 PDF / CSV 对账单留到 Phase 5，现在先手动录入账单余额。

## 10. 决策记录（2026-10-03）

- 手续费单独成类，放在税费大类；以后可被手续费免除冲减。
- 房产税、印花税放住房；历史税费先不拆。
- 房产 tag 用于房贷、物业、水电燃气、房产税、印花税和租金收入。成员 tag 只留字段，取值以后配置。
- 课外班一个类别 + 商家区分课程；学费独立保留。
- 交通拆为用车和出行；路税放用车。
- 报销状态三个值：待提交 / 已提交待到账 / 已到账。
- 回款以收入记录承载，可关联零到多笔支出，或按总额冲减待回款池。
- 收入分四个大类，性质分真实收入 / 冲减项；报表剔除冲减项。
- 「报销代付」大类改名为「代付款」，保留原小类；出差、代付场景的餐费、交通等按场景记在这里，不记到餐饮、出行。
- 报销不是必填项：取消「是否报销」开关，改为可选的「可回款金额」（默认 0）。记账时拆分自付和可回款部分（如 AA 聚餐刷 300、朋友还 240、自付 60），只有可回款部分进待回款池。
- 信用卡 min-spend 永远按刷卡全额计算；消费报表按自付金额计算。
- 支出性质分三种：生活消费、财务支出（保险理财、税费）、过手款（代付款）。前两种是真实流出，计入支出报表和预算；过手款因为有回款，不占支出和预算。「其他」大类归为生活消费。
- 新增账本：日常（默认）、旅行、房产出租；出租账本默认不计入家庭总支出，单独看损益；可以有账本专属类别。
- 新增类别：住房 / 维修装修；旅行账本专属「旅行」大类；出租账本专属「出租成本」大类；回款类 / 返现。
- 所有回款类收入必须填账户。消费退款到信用卡从 min-spend 扣除；信用卡返现不计入 min-spend。信用卡和银行账户的完整设计以后再做。
- 收入和支出放同一张交易表；类别名称先只用中文。
- 支付方式：账户分信用卡、银行、借记卡、储值账户、现金；自己账户之间的资金移动记为转账，不算支出或收入；信用卡充值储值卡逐笔选择是否计入 min-spend（默认否）；不设附属卡；暂不做多币种钱包；还卡账单先手动记为转账。
- 租金不计入家庭收入：租金收入大类只能在出租账本里使用，每套出租房的全部收入和开销都记在它自己的账本里，单独看损益（2026-10-03，v0.4.1）。
- 需求追溯检查（design/rtm.md）发现的问题：信用卡逾期还款状态、未关联的退款/手续费免除不再冲减回款池、手续费免除可直接关联手续费，均在 v0.4.1 修正。
- 信用卡年费、滞纳金/利息：新增「税费 / 卡年费」「税费 / 滞纳金利息」；这些费用和手续费刷在卡上但永远不计入 min-spend；之后被免除时，手续费免除关联原费用，原费用不再算支出，min-spend 不变（v0.4.1）。
